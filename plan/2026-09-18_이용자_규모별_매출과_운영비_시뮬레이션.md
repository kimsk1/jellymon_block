# 이용자 규모별 매출과 운영비 시뮬레이션

작성일: 2026-09-18

매일 플레이하는 사용자(DAU)가 1,000명·10,000명·100,000명인 경우를 비교한다. 기준 시나리오의 월 광고 수익과 아이템 결제액 합계는 각각 72만 원·720만 원·7,200만 원이다.

실적 예측이나 매출 보장이 아닌 가정에 따른 사업성 계산이다. 누적 다운로드 수나 월 활성 사용자 수가 해당 인원이라는 의미라면 이 계산을 그대로 적용할 수 없다.

## 1. 계산 가정

| 항목 | 기준 가정 |
|---|---|
| 기간 | 30일 |
| 월 활성 사용자(MAU) | DAU의 5배 — 이용자당 월평균 6일 접속 |
| 광고 | 전체 이용자 평균 하루 실제 노출 2회 |
| 광고 eCPM | 1,000회 노출당 7,000원 |
| 월 구매율 | MAU의 1% |
| 구매자 월평균 결제액 | 6,000원 |
| 스토어 수수료 | 세금 제외 결제액의 15% |
| 환율 | 예산 계산용 $1 = 1,400원 |

광고 횟수는 광고 요청이나 버튼 클릭이 아닌 실제 노출이다. eCPM과 구매율은 시장 평균이나 젤리몬에서 검증된 수치가 아니다.

스토어 수수료 15%는 관련 프로그램 가입과 자격 충족을 전제로 한다. 연간 실적과 프로그램 기준에 따라 달라지므로, 특히 낙관적 시나리오를 연간 운영비로 확장할 때는 재계산해야 한다.

- [Apple Small Business Program](https://developer.apple.com/app-store/small-business-program/)
- [Google Play 서비스 수수료](https://support.google.com/googleplay/android-developer/answer/112622)

## 2. 월 광고 수익과 아이템 구매액

금액 단위: 만원/월. 광고 수익은 광고 네트워크의 개발자 수익 기준이며 Adiz 비용 차감 전이다. 아이템은 이용자 결제액이다.

| 항목 | DAU 1,000명 | DAU 10,000명 | DAU 100,000명 |
|---|---:|---:|---:|
| 월 활성 사용자 | 5,000명 | 50,000명 | 500,000명 |
| 월 광고 노출 | 6만 회 | 60만 회 | 600만 회 |
| 광고 수익 | 42 | 420 | 4,200 |
| 월 구매자 | 50명 | 500명 | 5,000명 |
| 아이템 결제액 | 30 | 300 | 3,000 |
| 단순 합계 | 72 | 720 | 7,200 |

계산식:

- 광고: `DAU × 30일 × 2회 ÷ 1,000 × 7,000원`
- 아이템: `MAU × 구매율 1% × 6,000원`

영구 VIP처럼 한 번만 구매하는 상품은 같은 이용자에게 매월 반복 매출이 발생하지 않는다. 위 구매액을 유지하려면 신규 구매자 유입이나 소모품·시즌 상품의 반복 구매가 필요하다.

## 3. Hive 사용 시 월 비용

### 과금량 및 단가 가정

- 인증: 하루 2회/DAU. 월 30,000회 무료, 초과 회당 $0.002.
- 랭킹: 하루 5회/DAU. 월 15,000회 무료, 초과 회당 $0.00004.
- 결제: 구매자당 월 2건, 거래당 과금 대상 API 1회. 월 1,000회 무료, 초과 회당 $0.04.
- 게임 데이터: MAU당 100KB(십진 단위). API 호출 무료, 저장 10GB 무료, 초과 1GB당 $0.20.
- Adiz: 광고 수익의 7%.

[Hive 공개 요금표](https://www.hiveplatform.ai/pricing) 기준이다. 실제 계약 조건과 과금 대상 API 범위를 확인해야 한다. 인증·랭킹 호출 수는 최근 최적화 후 측정값이 아니다. 클라우드 저장 등에서 발생하는 인증도 실제 총량에 포함해 확인해야 한다.

금액 단위: 만원/월. 표의 금액은 반올림했다.

| 비용 | DAU 1,000명 | DAU 10,000명 | DAU 100,000명 |
|---|---:|---:|---:|
| 아이템 결제액에 포함된 부가세 | 2.73 | 27.27 | 272.73 |
| 스토어 수수료 15% | 4.09 | 40.91 | 409.09 |
| Hive 인증 | 8.40 | 159.60 | 1,671.60 |
| Hive 랭킹 | 0.76 | 8.32 | 83.92 |
| Hive 결제 API | 0 | 0 | 50.40 |
| Hive 게임 데이터 저장 | 0 | 0 | 1.12 |
| Adiz 7% | 2.94 | 29.40 | 294.00 |
| 자체 서버·백업·로그 예산 | 5~12 | 20~60 | 150~500 |
| 차감 후 잔액 | 41~48 | 395~435 | 3,917~4,267 |

### 계산식과 범위

```text
아이템 부가세 = 아이템 결제액 - 아이템 결제액 / 1.1
스토어 수수료 = 아이템 결제액 / 1.1 × 15%
Hive 인증료 = max(0, DAU × 30 × 2 - 30,000) × $0.002 × 1,400원
Hive 랭킹료 = max(0, DAU × 30 × 5 - 15,000) × $0.00004 × 1,400원
Hive 결제료 = max(0, MAU × 1% × 2 - 1,000) × $0.04 × 1,400원
저장료 = max(0, MAU × 0.0001GB - 10GB) × $0.20 × 1,400원
Adiz 비용 = 광고 수익 × 7%
잔액 = 광고 수익 + 아이템 결제액 - 위 비용 합계
```

- 부가세 계산은 비교를 단순화해 한국 결제만 있고 결제액에 부가세 10%가 포함된 것으로 가정했다. 국가별 실제 정산과 다르다.
- 결제료는 판매 건수 자체가 아닌 과금 대상 API 호출 기준이다. 실제 과금 API 범위와 재검증 횟수에 따라 증가한다.
- 저장량에는 탈퇴하지 않은 과거 이용자의 누적 데이터와 이력을 별도로 반영해야 한다.
- 서버 예산은 견적이나 부하 테스트 결과가 아니다. 현재 SQLite 서버를 그대로 확장해 10만 DAU를 처리할 수 있다는 의미가 아니다.
- 광고 네트워크 수익에 이미 반영된 수수료를 추가 차감하지 않는다. 실제 정산액에 Adiz 비용까지 포함돼 있으면 7%를 다시 차감하지 않는다.

잔액은 순이익이 아니다. 인건비·마케팅·콘텐츠 제작비·환불·소득세/법인세·개발자 등록비 및 서비스 청구서의 부가세 등은 제외했다.

## 4. AdMob 직접 연동 + 자체 백엔드 비교

같은 광고 수익과 구매액이 발생한다고 가정한다. 실제 서비스별 광고 수익이 동일하다는 보장은 없다.

자체 방식의 인프라 예산에는 인증·서버·DB·백업·모니터링을 포함했다. 인증 상품, 리전, 처리량, 저장량에 따라 실제 비용은 달라진다. 이는 공급자의 확정 견적이 아닌 계획용 예산 범위다.

- [Firebase 요금](https://firebase.google.com/pricing)
- [Cloud Run 요금](https://cloud.google.com/run/pricing)

금액 단위: 만원/월.

| 항목 | DAU 1,000명 | DAU 10,000명 | DAU 100,000명 |
|---|---:|---:|---:|
| 자체 방식 인프라 예산 | 10~25 | 40~120 | 300~1,000 |
| Hive 방식 잔액 | 41~48 | 395~435 | 3,917~4,267 |
| 자체 방식 잔액 | 40~55 | 532~612 | 5,518~6,218 |

자체 방식 잔액은 `광고 수익 + 아이템 결제액 - 아이템 부가세 - 스토어 수수료 - 자체 인프라 예산`으로 계산했다. Hive 인증·결제·랭킹·Adiz 요금은 없다. 대신 기능을 직접 개발·관리해야 하며, 추가 개발비와 운영 인건비는 표에 포함하지 않았다.

이 가정에서는 규모가 커질수록 자체 방식이 유리하며, 광고 수수료보다 인증 호출료가 더 큰 차이를 만든다.

### 인증 횟수 민감도

DAU 10만 명에서 인증을 하루 평균 2회에서 1회로 줄이면 인증료는 다음과 같다.

- 하루 2회: 월 1,671.6만 원.
- 하루 1회: 월 831.6만 원.
- 차이: 월 840만 원.

인증을 생략하는 것이 아니라 안전한 세션 관리와 중복 호출 제거로 달성해야 한다. 실제 호출 감소 효과는 배포 후 측정해야 한다.

## 5. 보수적·기준·낙관적 매출

아래 금액은 비용 차감 전 광고 수익과 아이템 결제액 합계다. 모든 시나리오에 MAU = DAU × 5를 적용했다.

| 시나리오 | 광고 가정 | 구매 가정 | 1,000 DAU | 10,000 DAU | 100,000 DAU |
|---|---|---|---:|---:|---:|
| 보수적 | 하루 0.5회, eCPM 3,000원 | MAU 0.5% × 4,000원 | 14.5만 원 | 145만 원 | 1,450만 원 |
| 기준 | 하루 2회, eCPM 7,000원 | MAU 1% × 6,000원 | 72만 원 | 720만 원 | 7,200만 원 |
| 낙관적 | 하루 4회, eCPM 12,000원 | MAU 3% × 10,000원 | 294만 원 | 2,940만 원 | 2억 9,400만 원 |

보수적 시나리오에서는 이용자가 많아져도 적자가 날 수 있다. 예를 들어 10만 DAU의 월 매출 합계 1,450만 원은 하루 인증 2회 가정의 인증료 1,671.6만 원보다 적다. 위 비용 표는 기준 시나리오용이며 다른 시나리오의 광고 수수료·결제 비용 등은 별도로 재계산해야 한다.

## 6. 실제 운영 판단

- 1,000 DAU: 기준 잔액 월 40만~55만 원으로 운영자 인건비 충당이 어렵다.
- 10,000 DAU: 기준 잔액 월 395만~612만 원. 작은 규모의 운영은 가능하지만 콘텐츠 제작비와 유입 광고비를 통제해야 한다.
- 100,000 DAU: 매출 잠재력은 크지만 인증 과금·장애 대응·고객 지원 비용을 별도로 관리해야 한다.

인건비 예시: 월 운영 작업 40시간 × 시간당 3만 원 = 120만 원. 이 경우 1,000 DAU는 기준 시나리오에서도 적자다. 이는 예산 예시이며 모든 규모를 40시간으로 운영할 수 있다는 뜻이 아니다.

마케팅비 예시: 신규 설치 1만 건 × 설치당 1,000원 = 1,000만 원. 신규 설치는 활성 사용자와 다르므로, 유지율과 이용자 생애 순수익이 유입 비용을 초과하는지 확인해야 한다.

우선 측정할 네 가지 지표:

1. 실제 광고 노출 수 / DAU.
2. 국가·OS·광고 유형별 eCPM.
3. 월 구매율과 구매자 월평균 결제액.
4. 과금 대상 인증 호출 수 / DAU.

실측 지표와 사용자 유지율을 확보한 후 가정을 대체해 운영 손익을 다시 계산한다.
