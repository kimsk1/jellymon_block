# Hive 인증 호출 최적화 구현

2026-09-18. 클라이언트와 서버 소스 수정 완료. 서버 배포 및 앱 재빌드는 별도 필요하다.

## 랭킹

- 기록 갱신은 최초 갱신 시점부터 30초 동안 모아 최신 최고 기록만 전송한다. 랭킹 화면 새로고침 시에는 즉시 전송한다(진행 중 요청/실패 재시도 대기 제외).
- HTTP 200 및 202 모두 서버 접수 완료로 처리한다. 202 이후 Hive 반영 재시도는 기존 서버 작업자가 담당한다.
- 접수 기록을 저장 파일 옆 `.ranking-ack` 파일에 보관해 앱 재시작 후 같은 기록을 다시 인증/전송하지 않는다. 서버 주소, App ID, 플레이어 ID로 구분한다. 아직 전송하지 않은 최고 기록은 기존 게임 저장 데이터로 보존된다.
- 실패 재시도는 1분부터 두 배씩 늘리고 최대 15분으로 제한한다. 동시 재시도 집중을 줄이기 위한 무작위 지연을 포함한다.
- HTTP 401이면 반복 호출을 중단하고 새 로그인 이벤트를 기다린다.
- 서버 접수 파일은 계정 인증이나 보상 지급의 근거가 아니다. 서버 DB를 유실하면 접수된 기록 복구가 필요하므로 기존 DB 백업을 유지해야 한다.

## 상점

- 상품 가격은 메모리에 5분 보관한다. 빈 상품 목록은 재조회할 수 있다.
- 상점을 다시 열거나 정상 상태에서 앱으로 복귀할 때마다 서버 구매 내역 및 SDK 복원을 반복하지 않는다. 가격 캐시 만료 시에는 가격만 갱신한다.
- 로그인, 명시적인 구매 복원 버튼, 미완료 구매의 복구 시에는 구매 내역과 SDK 영수증을 다시 확인한다.
- 실제 구매는 기존 주문 → Hive 영수증 검증 → 로컬 지급 저장 → 서버 ACK → SDK 거래 완료 순서를 유지한다.
- 다른 기기 구매가 현재 세션 도중 발생한 경우 구매 복원 버튼으로 반영할 수 있다.

## 서버

- 동일 환경/App ID/플레이어/기기/플레이어 토큰/액세스 토큰의 동시 인증은 하나의 진행 중 Hive 요청에 합류한다. 토큰 원문 대신 SHA-256 키를 사용한다.
- 성공 결과 캐시는 기본 비활성화(`HIVE_AUTH_CACHE_SECONDS=0`). 동시 요청 합치기는 캐시와 별도로 작동한다.
- Hive 중복 로그인 정책과 토큰 사용 방식을 확인한 뒤에만 `HIVE_SINGLE_LOGIN_CONFIRMED=true`와 `HIVE_AUTH_CACHE_SECONDS=60` 등으로 활성화한다. 허용 범위는 0~300초다. 확인 플래그 없이 활성화하면 서버 시작을 거부한다.
- 유효 기간은 최초 인증 요청 시점 기준 고정 TTL과 검증받은 토큰의 exp 5초 전 중 짧은 쪽이다. 접근할 때마다 연장하지 않는다. exp를 알 수 없는 토큰은 캐시하지 않는다.
- 인증 실패는 캐시하지 않으며 같은 키의 기존 성공 캐시도 제거한다. 메모리 캐시와 진행 중 요청 수에 상한을 둔다.
- `/v1/billing/verify`에서는 저장된 인증 캐시를 우회하고 Hive에 검증한다. 동일 토큰의 진행 중 원격 인증에 합류할 수는 있다. 결제 영수증 검증 자체는 생략하지 않는다.
- 프로세스별 메모리 캐시이므로 서버 여러 대 사이에는 공유하지 않는다.

## 측정 및 반영

서버는 60초마다 `[auth-metrics]` 누적 지표를 기록한다. `requests`는 서버 인증 함수 진입 횟수, `upstream`은 실제 Hive 인증 시도(대체 호스트 재시도 포함), `joined`는 진행 중 요청 합류, `hits`는 성공 캐시 적중, `failed`는 원격 인증 작업 실패다. 토큰 및 플레이어 ID는 지표에 포함하지 않는다.

실제 과금 감소량은 배포 후 같은 기간의 Hive 사용량과 upstream 증분으로 판단한다. 이 변경은 Cloud Save 등 다른 SDK 인증 호출을 전부 제거하는 변경은 아니다. 운영 `.env`, Hive 콘솔 정책, 배포 서버는 이번 작업에서 변경하지 않았다.

## 검증

- 서버 `npm test`: 26개 통과. 동시 요청 합치기, 고정 TTL, 만료 상한, 토큰/계정/기기 격리, 실패 후 재검증, 캐시 우회 및 기존 결제/랭킹 회귀 검사.
- Godot `tools/tests/auth_calls_test.tscn`: 30초 묶음 전송, 202 및 재시작 후 중복 전송 방지, 401 중단, 실패 백오프, 가격 캐시, 명시적 복원, 중단된 구매 복구 통과.
- 클라이언트 테스트는 가짜 플랫폼 이벤트를 사용한다. 실제 Hive 요청, 실제 결제, 운영 배포는 하지 않았다. 헤드리스 실행에서 macOS 시스템 CA 접근 경고가 발생했지만 테스트는 종료 코드 0 및 PASS로 완료됐다.
