# 젤리몬 구조대 — 정식 출시 완성도 진단 및 매출 분석

작성일: 2026-09-11
기준: `game/` 작업 트리(커밋되지 않은 변경 포함), `docs/` 내 검증 기록, `output/JellyMon.apk`(2026-09-10 빌드), 2026년 모바일 게임 공개 벤치마크.
성격: 코드·데이터·문서를 정적으로 대조한 진단. 이번 작업에서 실기기 실행이나 자동 플레이를 새로 수행하지는 않았다.

## 1. 한 줄 요약

**게임 자체(퍼즐·1,000레벨·메타 콘텐츠)는 약 85~90% 완성됐지만, "돈을 받고 서비스할 수 있는 상태"를 기준으로 보면 전체 완성도는 약 55~60%다.** 남은 40%는 콘텐츠가 아니라 결제·서버·스토어 등록·정책 문서·QA 같은 출시 인프라이고, 이 중 어느 하나라도 빠지면 심사 반려 또는 매출 0원이 된다.

매출은 마케팅 없이 자력 출시할 경우 **첫 3개월 월 ₩20만~₩120만** 수준이 가장 현실적인 기대치다. 현재 수익화 설계(강제 광고 없음, 최고가 상품 ₩6,500)는 "유저당 매출"이 장르 평균보다 낮게 나오는 구조라서, 매출을 키우려면 유저 수 확보와 별개로 ARPDAU를 3~5배 끌어올리는 작업이 필요하다.

## 3. 출시 차단 항목 (P0 — 이것 없이는 출시 불가)

### 3.1 결제

1. **Android 결제 실기기 실패 해결** — 현재 `IAPV4ResponseError(-6100011) Invalid market pid list`. Google Play Console에 단건 상품 8개 등록 + 구매 옵션 활성화 → Hive 콘솔 `[3674]`의 Android App ID에 동일 marketPid 매핑 → 라이선스 테스터 결제 → 취소/복원/재전송/앱 종료 시나리오 12개(문서 7장 표) 전부 통과.
2. **iOS 결제 전 과정** — App Store Connect 상품 8개 등록, 유료 앱 계약·세금·은행 정보 완료, Hive iOS 상품 매핑, Sandbox 계정 구매·복원 검증. 현재 0단계.
3. **결제 서버 상용 배포** — `platform_services.json`의 `api_base_url`이 ngrok 개발 주소. 고정 도메인 + HTTPS + 상시 실행 + SQLite 백업 스케줄 필요. 서버가 죽으면 상점이 열리지 않는 구조이므로 가용성 모니터링(헬스체크 알림) 필수.
4. **Hive zone sandbox → live 전환** — 앱(Android `platform_services.json`, iOS `hive_config.xml` 2곳), 서버 `HIVE_ZONE`, Hive 콘솔 라이브 상품·스토어 설정. 두 플랫폼이 서버를 공유하므로 환경 분리 계획 확정.
5. **환불 처리 정책** — 현재 지급 후 환불 통지를 받아 회수하는 기능 없음. 최소한 운영 매뉴얼(수동 회수·VIP 해제 절차)은 출시 전 문서화. RTDN/App Store Server Notifications 연동은 출시 직후 P1.

### 3.2 광고

6. `test_ads=true` + Google 테스트 App ID 상태. AdMob 앱·Rewarded 광고 단위를 Android/iOS 각각 생성 → Hive Adiz 매핑 → 실제 ID 적용 후 재빌드. iOS 보상형 광고는 실기기 왕복 검증 기록 없음.
7. iOS **ATT(앱 추적 투명성) 프롬프트**와 `NSUserTrackingUsageDescription` — AdMob 사용 시 필요. export preset의 `privacy/tracking_enabled=false` 상태 재검토.
8. 글로벌 출시 시 **GDPR/UMP 동의 폼**(EEA·UK) — 한국 단독 출시라면 생략 가능.

### 3.3 스토어 등록·정책(양 플랫폼 공통 심사 필수)

9. **개인정보처리방침 URL** — Hive가 기기 식별자·로그인 정보를 수집하므로 필수.
10. **계정 삭제 URL·앱 내 삭제 경로** — Google Play(계정 생성 앱 필수)와 Apple(로그인 지원 앱 필수) 모두 요구. 현재 "연결 해제"는 기기 데이터 초기화이지 계정 삭제가 아님 → Hive 계정 삭제 API 연동 또는 삭제 요청 접수 절차 필요.
11. **고객지원 이메일·웹사이트**, 개발자/판매자 명의.
12. **Google Play 데이터 안전 섹션 / Apple 개인정보 라벨** — export preset의 `collected_data/*`가 전부 false인데 실제로는 식별자·구매 기록·분석 이벤트를 수집. 실제와 다르게 제출하면 반려·삭제 사유.
13. **콘텐츠 등급 설문(IARC)** — 광고 포함·IAP 포함으로 응답.
14. **스토어 자산** — 아이콘 1024px(iOS preset 슬롯 전부 공란), 세로 스크린샷 각 플랫폼 규격, 피처 그래픽(Google), 미리보기 영상(권장).
15. **심사용 접근 정보** — 상점 도달 방법, 테스트 계정.

### 3.4 빌드

16. **APK 374MB 문제** — 원인: `tmp/`의 Keynote 파일(약 100MB), `docs/` PPTX 12MB, x86_64 라이브러리 81MB, 서버·네이티브 소스 등이 전부 리소스로 패키징됨. `tmp/`, `docs/`, `server/`, `native/`, `build/`, `output/` 전체에 `.gdignore` 추가 또는 export `exclude_filter` 설정, `architectures/x86_64=false`, 루트의 `sync_now.tgz`·`zi1LjBtV`·`ziqDdOWi`(각 26MB) 제거. 예상 결과 60~90MB. Google Play는 AAB 필수, iOS는 셀룰러 다운로드 200MB 한도 이슈.
17. **Android release 서명** — 업로드 키 생성·보관, Play App Signing 등록. 현재 preset은 debug 흐름 위주.
18. **Android `permissions/internet=false`** — Gradle 플러그인이 권한을 추가하고 있더라도 preset에서 명시적으로 켜서 빌드 변형 간 차이를 없애야 함.
19. **iOS 번들 ID** — `com.jellymontest.game`(테스트 ID). 정식 ID로 App ID·프로비저닝·Hive App ID·Google OAuth Client·URL Scheme을 모두 재발급·교체. 서버 `HIVE_IAP_IOS_APP_ID`/`HIVE_IAP_IOS_BUNDLE_ID`도 함께.
20. **버전 정보** — Android `version/name` 공란, iOS `short_version`/`version` 공란. 1.0.0 / code 1로 설정.
21. **iOS 릴리스 템플릿 호환** — 브리지가 `DEBUG_ENABLED`로 컴파일됨. release export template과 ABI 호환 검증, Archive → TestFlight 1회 완주 필요.
22. **미커밋 변경 27개 파일**(iOS 브리지 바이너리, BillingService, Game, Levels 등) — 출시 빌드 기준을 잡기 위해 커밋·태그.

### 3.5 안정성·QA

23. **iOS 클라우드 저장 HTTP 500** — Hive 지원팀 trace ID 전달 후 회신 대기 중. 해결 전엔 iOS 스토어 소개에서 클라우드 저장 언급 제외.
24. **랭킹 API `/v1/ranking/top` 502** — 서버 재배포 후 실기기 등록·조회 확인. 미해결 시 랭킹 메뉴를 기능 플래그로 숨기고 출시.
25. **L161 자동 탐색 실패** — 수동 풀이로 클리어 가능 여부 확정. 불가능하면 재베이크.
26. **크래시 리포트 부재** — Firebase Crashlytics(또는 Hive 제공 크래시 도구) 연동. 출시 후 첫 주에 크래시율을 모르면 대응 불가.
27. **원격 분석 비활성** — `analytics_remote.json` `enabled=false`, endpoint 공란. 수집 서버(자체 엔드포인트 또는 Firebase Analytics 대체) 결정·연결. 이것 없이는 아래 4장의 매출 개선 작업 전부가 감으로 진행됨.
28. **기기 매트릭스 QA** — 저사양 Android(4GB 이하), 노치·다이내믹 아일랜드 iPhone, iPhone SE(작은 화면), 태블릿 세로. 현재 실기기 기록은 Galaxy Note10 1대 + iPhone 1대.
29. **시작 시간** — Note10 기준 첫 프레임 3.2초. 스플래시 표시·부트 씬 분리로 체감 개선(문서에 우선순위 기재됨).

35. **원격 설정(Remote Config)** — 행동력 회복 시간·이어하기 비용·광고 배치 on/off를 앱 업데이트 없이 조정할 수 있어야 함.

## 5. 매출 추정

### 5.1 전제와 벤치마크

- 환율 ₩1,400/$ 가정. 스토어 수수료 15%(연 매출 100만 달러 이하 소규모 개발자 프로그램) 차감 전 총매출 기준.
- 장르 벤치마크(2025~2026 공개 자료): 업계 중앙값 리텐션 D1 26% / D7 10% / D30 3~4%, "양호" 30~35% / 15% / 5%. 캐주얼 광고 중심 ARPDAU $0.01~0.05, 하이브리드 캐주얼(광고+IAP) $0.15~0.50. 한국 보상형 광고 eCPM Android $22 / iOS $21(미국 $30 / $24). 결제 전환율 통상 1% 안팎. 퍼즐 CPI iOS 약 $3, Android 약 $2(글로벌 평균, 한국은 이보다 높은 편).
- 비교 대상 빠지냥(Drop the Cat, ACTIONFIT): Google Play 100만+ 다운로드, 4.4점, 리뷰 5.7만. 같은 룰의 선발 주자가 시장을 이미 검증했다는 뜻이자, 후발 주자가 "차별화"를 스토어 첫 화면에서 증명해야 한다는 뜻.

### 5.2 현재 설계의 ARPDAU 추정(왜 낮게 나오는가)

젤리몬은 강제 전면 광고가 없고 보상형 광고 배치가 사실상 "클리어 보상 2배" 1곳이다. 광고 수락률 25%(내부 목표) × 유저당 하루 클리어 4~6회를 가정해도 DAU당 노출 1.0~1.5회, 한국 eCPM $21 기준 **광고 ARPDAU 약 $0.02~0.03**. IAP는 최고가 ₩6,500·비소모 상품 위주라 반복 구매 동력이 약하고, DAU 대비 월 결제자 2~3% × 평균 ₩8,000을 가정하면 **IAP ARPDAU 약 $0.005~0.01**. 합산 **현재 설계 ARPDAU ≈ $0.025~0.04**. 이는 "캐주얼 광고 중심" 범위의 중간이고 하이브리드 캐주얼 하한($0.15)의 1/4 수준이다.

| A′. 자력 출시 + 6장 개선 적용 | 동일 유입, ARPDAU 3배 | 200~600 | $0.08~0.12 | ₩70만~₩300만 | ₩1,000만~₩3,000만 |
| B. 소규모 UA (월 ₩300~500만) | 한국 Android CPI ₩1,500~3,000, 월 3~6천 설치 + 오가닉 | 800~1,500 | $0.05~0.08 | ₩170만~₩500만 | ₩2,000만~₩5,000만 (광고비 ₩3,600만~6,000만 별도 → **순손실**) |
| C. 피처드·바이럴 | 스토어 추천 또는 숏폼 바이럴, 첫 달 5만~20만 설치 | 5,000~20,000 (피크) | $0.08~0.15 | 피크 월 ₩1,700만~₩1억2천만, 3개월 내 60~80% 감소 | ₩1억~₩5억 |

**가장 가능성 높은 결과는 A**다. B는 현재 설계에서 설치당 기대 매출(LTV ≈ ARPDAU × 평균 생존일 8일 ≈ ₩300~450)이 CPI(₩1,500 이상)의 1/4에도 못 미치므로 광고비를 쓸수록 손해다. **유료 UA는 6장의 개선으로 LTV가 CPI를 넘긴 뒤에만 의미가 있다.** C는 노력으로 확률을 높일 수는 있어도 계획에 넣을 수 없다.

### 5.4 손익 관점

고정비로 서버(월 ₩3~10만), 도메인·SSL, Apple 개발자 연회비 $99, Google 등록비 $25(1회)가 든다. 시나리오 A에서는 첫 3개월 매출로 서버비 정도만 상쇄된다. Hive 플랫폼 이용 조건(수수료 유무)은 계약서로 재확인이 필요하다.

주의: 위 수치는 공개 벤치마크와 현재 설계를 바탕으로 한 추정이며, 실제 성과는 베타 실측치로 대체해야 한다. 재무·투자 판단의 근거로 단독 사용하지 않기를 권한다.

## 6. 매출을 늘리기 위한 작업 (우선순위순)

### 6.1 0순위 — 측정 없이는 아무것도 못 고친다

- 원격 분석 활성화(27번)와 크래시 리포트(26번). 25개 이벤트 스키마는 이미 있으므로 수집 서버 연결이 전부다.
- 클로즈드 베타(30번)에서 **레벨별 이탈 지점·광고 제안/수락률·상점 노출→구매 전환**을 측정하고, 출시 전 초반 20레벨을 데이터로 재조정.
- 대시보드는 거창할 필요 없음. 일 단위 DAU·신규·D1/D7·ARPDAU·광고 노출/DAU·결제자 수 7개 숫자만 매일 볼 수 있으면 된다.

### 6.2 1순위 — 광고 ARPDAU 3배 (구현 난도 낮음, 효과 즉시)

현재 광고 배치 1곳을 **4~5곳**으로 늘려 DAU당 노출 3~4회를 목표로 한다. 전부 선택형이므로 "강제 광고 없음" 원칙과 충돌하지 않는다.

1. **실패 시 이어하기를 광고로** — 현재 별가루 20개 이어하기 옆에 "광고 보고 이어하기(하루 N회)" 추가. 퍼즐 장르에서 수락률이 가장 높은 배치.
2. **하트 0개일 때 광고로 하트 1개** — 행동력 벽에서 이탈하는 유저를 붙잡는 배치. 하루 3~5회 상한.
3. **홈 일일 무료 선물(광고)** — 로그인 직후 별가루·부스터 소량. 세션당 1회 확정 노출.
4. **부스터 무료 체험(광고)** — 시간·나침반 부스터를 광고로 1개.
5. **클리어 보상 2배(기존)** — 유지.

기대 효과: 노출 1.2회→3.5회/DAU, 한국 eCPM 유지 시 광고 ARPDAU $0.025→$0.07.

전면 광고(레벨 사이 인터스티셜)는 ARPDAU를 추가로 $0.03~0.05 올릴 수 있지만 D1이 2~4%p 떨어지는 것이 일반적이다. 원칙을 지키되, 베타에서 A/B로 "5레벨마다 1회·VIP 면제" 변형을 한 번은 측정해 보는 것을 권한다. 측정 없이 배제하면 매출의 상당 부분을 이념적으로 포기하는 셈이다.

### 6.3 2순위 — IAP 구조 보강 (구현 난도 중간)

현재 카탈로그의 문제는 셋이다. 최고가가 ₩6,500이라 많이 쓰고 싶은 유저가 쓸 수 없고, 비소모 상품(팩 3종·VIP)은 각 1회면 끝나며, 별가루의 반복 소비처가 이어하기(20개)와 가구뿐이라 재화 구매 동기가 약하다.

1. **가격 사다리 확장** — 별가루 ₩5,900 / ₩12,000 / ₩25,000 티어 추가(보너스 % 체증). 상위 1% 결제자가 매출의 절반을 내는 구조를 열어 둔다.
2. **별가루 소비처 추가** — 하트 즉시 충전(별가루), 부스터 상점(별가루), 주간 한정 가구 로테이션(별가루), 아지트 새 방 해금(별가루 대량). "별가루가 모자란 순간"이 매일 생겨야 별가루 상품이 팔린다.
3. **저금통(Piggy Bank)** — 클리어할 때마다 별가루가 쌓이고 ₩2,900~4,900에 개봉. 캐주얼 퍼즐에서 첫 결제 전환율을 가장 잘 올리는 검증된 상품.
4. **스타터 팩 타이머** — 새내기 팩을 "첫 48시간 한정 -70%" 노출로 바꿔 긴급성 부여. 현재 추천 로직(클리어 30회 미만)은 유지.
5. **시즌 패스 반복성** — 시즌 2·3 데이터 미리 준비. 시즌 종료 3일 전 알림. 현재 S1 하나뿐이라 28일 후 상품이 사라진다.
6. **VIP 재정의** — 현재 VIP(₩3,000 영구)는 광고 1회 면제라 가치가 흐릿하다. "월 ₩4,900 구독: 하트 무제한 + 별가루 매일 30 + 보상 광고 즉시 완료 무제한"으로 바꾸면 구독 매출(업계 비중 4%→7%로 성장 중)이 열린다. 자동 갱신 구독은 스토어 등록·서버 검증 로직이 별도 필요.
7. **결제 실패 지점 제거** — 상점 진입이 L10 해금, VIP 혜택 UI가 L15 해금(33번). 구매 가능 시점과 혜택 확인 시점을 일치시킨다.

기대 효과: IAP ARPDAU $0.007→$0.03~0.05.

### 6.4 3순위 — 리텐션 (매출의 곱셈 항)

D7을 10%→15%로 올리면 같은 유입에서 DAU와 매출이 약 1.4배가 된다.

1. 푸시 알림(32번): 하트 충전 완료·일일 리셋·주민 부탁·시즌 마감.
2. 첫 세션 목표: L10 도달 55%를 넘길 때까지 L1~10 난이도·튜토리얼을 베타 데이터로 조정. 초반 20레벨 실패 후 이탈 12% 이하가 관문.
3. 첫 3일 리워드 캘린더(출석과 별도): D1·D2·D3 복귀 보상을 앞에 몰아 D1을 끌어올린다.
4. 하트 회복 10분·최대 5개는 적절. 다만 하트가 0일 때 "할 수 있는 다른 일"(꾸미기·앨범·주민 부탁)로 안내하는 UI가 있어야 세션이 유지된다.
5. 주간 원정·랭킹은 이미 있으므로 서버(24번)만 안정화하면 된다.

### 6.5 4순위 — 유입 (돈 안 드는 것부터)

1. **한국 우선 출시** — 한국 eCPM은 미국 다음으로 높고, 한국어 UI가 완성돼 있으며, 빠지냥 유저층이 그대로 잠재 고객이다. 글로벌은 로컬라이즈(31번) 완료 후 일본→미국 순.
2. **ASO** — 제목·부제에 "퍼즐", "구조", "꾸미기" 키워드. 스크린샷 1·2장은 손맛(가두기 이펙트)과 아지트를 보여준다. 빠지냥과의 차이(주민·아지트·보스)를 첫 화면에서 설명.
3. **스토어 피처드 신청** — Google Play 인디 게임 페스티벌(한국 개최), Apple 피처링 신청 폼. 출시 4~6주 전에 제출.
4. **숏폼** — "한 번에 5마리 쓸어 담기" 15초 영상은 제작비가 거의 들지 않고 이 장르에서 바이럴 확률이 가장 높은 소재다. 클리어 화면에 공유 버튼(현재 촬영 모드 존재)을 연결.
5. **커뮤니티** — 퍼즐 게임 카페·디스코드·트위터 인디 게임 태그. 베타 테스터 모집을 여기서 시작하면 출시 초기 리뷰가 확보된다.
6. **유료 UA** — 6.2·6.3 적용 후 LTV(D30 기준)가 CPI의 1.2배를 넘는 것이 확인되면 월 ₩100만 단위로 시작. 그 전에는 쓰지 않는다.

### 6.6 개선 후 기대치

6.2~6.4를 모두 적용하면 ARPDAU $0.10~0.15, D7 15%가 현실적 목표다. 시나리오 A 유입 그대로여도 **월 ₩100만~₩400만**, 피처드가 붙으면 **월 ₩3,000만 이상**이 가능한 구조가 된다. 반대로 개선 없이 출시하면 유입이 10배가 되어도 월 ₩200만~₩800만에 머문다. **매출 레버는 유입보다 유저당 매출과 리텐션에 있다.**
