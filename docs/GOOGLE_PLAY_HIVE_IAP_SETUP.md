# 젤리몬 Google Play · Hive 인앱 결제 등록 및 테스트 가이드

작성일: 2026-09-10. 대상: **Android Google Play 단건 결제**. iOS App Store 결제는 별도 [iOS · Hive IAP 가이드](IOS_HIVE_IAP_SETUP.md)를 참고하세요.

## 1. 현재 적용 범위와 진행 순서

앱의 기존 상점 상품 8개를 Hive IAP v4와 연결했습니다. 개발 빌드에서 버튼만 눌러 무료 지급하던 경로는 제거했습니다. 이제 Google Play 구매 결과를 받아도 서버 검증과 지급 저장이 성공해야 거래를 완료합니다.

| 구분 | 이번 작업 |
|---|---|
| Android 앱 | 결제 SDK 포함, 상점 초기화, 스토어 가격 표시, 구매, 미완료 구매 복원, 거래 완료 처리 |
| Node.js/TypeScript 서버 | Hive 로그인 검증, 구매 주문 생성, Hive 영수증 검증, 거래별 지급 이력, 중복 방지, 영구 상품 소유권 조회 |
| 게임 저장 | 지급 내용과 거래 처리 표시를 하나의 파일에 원자 저장, 저장 실패 시 메모리 지급 취소 |
| 상점 UI | 실제 스토어 가격, 처리 중 중복 클릭 방지, 구매 복원/상품 새로고침 버튼, 오류 안내 |
| Google/Hive Console | 아래 순서대로 운영자가 등록해야 함. 이번 작업에서 콘솔 등록·출시를 수행하지 않음 |
| 실결제 | 라이선스 테스트 완료 전 실제 판매를 열지 않음. 테스트 성공 여부는 마지막 검증 기록 참고 |

진행 순서:

1. Google Play에 앱 등록, 결제 프로필 준비.
2. 아래 표의 단건 상품과 한국 가격 등록·활성화.
3. Google 서비스 계정/라이선스 키를 Hive Google 스토어 설정에 연결.
4. Hive에 같은 상품 ID 등록.
5. 새 서버 코드 배포 후 IAP 설정을 켜고 재시작.
6. 테스트폰 Google 계정을 **라이선스 테스터**로 등록.
7. 새 APK 또는 내부 테스트 AAB로 테스트 결제·취소·복원 확인.
8. 실판매 전 미완료 항목을 검토하고 운영 환경으로 전환.

### 2.1 등록 화면 순서

1. Google Play Console에서 **모든 앱 → 앱 만들기**를 엽니다.
2. 위 앱 이름·언어·게임·무료 항목을 입력합니다.
3. 개발자 계정의 판매자/결제 프로필 등록을 완료합니다.
4. 앱의 기본 스토어 등록정보에 아래 소개 문구와 실제 앱 스크린샷을 등록합니다.
5. 앱 콘텐츠 항목에서 광고, 앱 액세스, 콘텐츠 등급, 타겟층, 데이터 보안 등을 작성합니다.
6. 내부 테스트용 서명된 AAB를 업로드할 때 패키지가 `com.jellymon.game`인지 확인합니다. 앱 서명용 키와 업로드 키를 안전하게 관리합니다.

이름/소개는 **등록 초안**입니다. 실제 서비스명, 고객지원 정보, 정책 URL은 운영자가 확정해야 합니다. 현재 앱의 연결 해제는 기기 데이터 초기화이므로, 이를 서버/Hive 계정의 영구 삭제라고 안내하면 안 됩니다.

### 2.4 등록 이미지와 앱 콘텐츠 자료

- 앱 액세스 심사에 로그인이나 특정 레벨 조건이 필요하면 심사자가 상점에 도달할 수 있는 실제 방법을 제공합니다.

## 3. 상품과 한국 판매 가격

원본: `assets/data/item.json`. 서버 배포용 동일 사본: `server/leaderboard/config/iap-products.json`.

**8개 모두 단건 상품입니다. 자동 갱신 구독을 만들지 않습니다.** 표의 '반복 구매'는 게임의 지급 정책입니다. Play의 상품 유형은 단건 상품으로 등록하고, 소비/소유권 처리는 앱·Hive·서버가 수행합니다.

표의 가격은 기존 기획값입니다. Play Console의 대한민국 최종 사용자 가격을 이 값에 맞추고, 통화별 허용 가격/세금/자동 환산 결과를 저장 전에 확인하세요. 콘솔이 특정 금액을 허용하지 않는다면 기획 가격 변경 여부를 먼저 결정해야 합니다. 앱은 등록 후 SDK의 `displayPrice`를 표시하므로 해외 사용자에게 한국 고정 가격을 표시하지 않습니다.

## 4. Google Play 상품 등록 — 8개 반복

현재 콘솔에서는 기존 '인앱 상품' 대신 **Play로 수익 창출 → 제품 → 일회성 제품/단건 상품(One-time products)** 메뉴가 보일 수 있습니다. 단건 상품에는 구매 옵션이 필요하고 활성화된 옵션이 SDK 조회 대상입니다. [Google 단건 상품 안내](https://support.google.com/googleplay/android-developer/answer/16430488?hl=ko)

1. `com.jellymon.game` 앱을 선택합니다.
2. 단건 상품 메뉴에서 상품 만들기를 누릅니다.
3. 표의 상품 ID를 그대로 입력합니다. 임의로 언더스코어나 패키지 접두사를 추가하지 않습니다.
4. 기본 언어 한국어, 상품명, 설명을 위 내용으로 등록합니다.
5. 세금/규정 관련 항목은 실제 판매자 정보로 작성합니다.
6. 구매 옵션 ID가 필요하면 각 상품 안에 `buy`라는 기본 옵션 1개를 만듭니다.
7. 구매 유형은 **Buy/구매**, 대한민국을 판매 가능 지역으로 설정하고 표의 KRW 가격을 입력합니다.
8. 수량 여러 개 구매, 선주문, 할인 오퍼, 외부 구매 추천/프로모션은 이번 연동에서 사용하지 않습니다. 기본 단일 수량 구매만 테스트합니다.

## 6. 결제 서버 반영

### 6.1 배포 파일

기존 `server/leaderboard` 서버에 IAP API를 추가했습니다. 별도 서버 도메인은 필요하지 않습니다. 서버 폴더 전체를 최신 버전으로 반영해야 하며 **`config/iap-products.json`도 반드시 포함**합니다. `dist`만 복사하지 마세요.

```sh
cd server/leaderboard
npm ci
npm run build
```

기존 `.env`의 로그인/랭킹 설정을 보존하면서 다음 항목을 추가합니다.

```dotenv
HIVE_APP_ID=com.jellymon.game
HIVE_ALLOWED_APP_IDS=com.jellymon.game,com.jellymontest.game
HIVE_LEADERBOARD_ID=163
HIVE_ZONE=sandbox
HIVE_IAP_ENABLED=true
HIVE_IAP_AUTH_KEY=
HIVE_IAP_ALLOW_REAL=false
```

- 기존 `HIVE_CERTIFICATION_KEY`는 유지합니다. 문서 예시로 덮어쓰지 않습니다.
- `HIVE_IAP_AUTH_KEY`: Hive 영수증 API 인증 사용 설정이 켜져 있을 때 해당 인증 키를 서버에만 넣습니다. OAuth Client Secret이나 DataStore 공개키를 넣는 칸이 아닙니다.
- `HIVE_IAP_ALLOW_REAL=false`: 테스트 영수증만 허용합니다. 단, 이 설정이 Google 결제창을 무료로 바꾸지는 않습니다. 반드시 Google 라이선스 테스터를 사용해야 합니다.
- `RANKING_DB_PATH`의 기존 SQLite DB와 WAL 파일을 보존합니다. 같은 DB에 구매 주문·지급 이력이 추가됩니다.

서버 운영 방식에 맞게 기존 프로세스를 중지하고 재시작합니다. 수동 실행이면 다음을 사용합니다.

```sh
npm start
```

다른 터미널에서 확인합니다.

```sh
curl -H 'ngrok-skip-browser-warning: true' \
  https://engrailed-sadye-curatively.ngrok-free.dev/healthz
```

정상 기대값:

```json
{"status":"ok","billing":true}
```

`{"status":"ok"}`만 나오면 이전 서버가 실행 중입니다. `billing:false`면 새 코드지만 IAP가 비활성화된 상태입니다. 상태 응답 성공은 Google/Hive 영수증 검증 성공까지 의미하지 않습니다.

### 6.2 앱에 연결한 API

| 경로 | 동작 |
|---|---|
| POST `/v1/billing/order` | 로그인·상품·기존 소유권 확인 후 구매 주문 생성 |
| POST `/v1/billing/verify` | SDK 영수증을 Hive로 검증, 주문 계정/앱/상품 대조, 거래별 지급 기록 생성 |
| POST `/v1/billing/ack` | 기기에 지급이 저장되었다는 확인을 기록 |
| POST `/v1/billing/entitlements` | 동일 Hive 계정의 영구 상품/현재 시즌 소유권 조회 |

서버는 임의의 클라이언트 상품 수량/가격을 지급 근거로 사용하지 않습니다. 배포된 서버 카탈로그와 Hive의 검증 결과를 사용합니다. 구매 주문 ID는 `iapPayload`에 넣고, Hive가 반환한 값과 서버 주문을 대조합니다. 영수증 원문은 로그/DB에 남기지 않습니다. [Hive 영수증 검증 API](https://developers.hiveplatform.ai/en/latest/api/hive-server-api/billing/verify-receipt/)

### 6.3 지급·복원 규칙

1. SDK 영수증 수신 → 서버 검증 → 기기에 재화와 거래 번호를 함께 저장합니다.
2. 디스크 저장 실패 시 지급 전 메모리 값으로 되돌리고 거래 완료를 호출하지 않습니다.
3. 서버에 지급 완료를 알린 다음 Hive `transactionFinish`를 호출합니다.
4. 앱 종료/통신 실패 후에는 로그인, 앱 복귀, 상점 새로고침에서 미완료 거래를 다시 조회합니다.
5. 동일 거래는 기기 거래 기록과 서버 기록으로 중복 지급을 막습니다.
6. 다른 기기에서 미완료 지급이 진행 중이면 구매한 기기에서 먼저 완료하도록 안내합니다.
7. 완료된 패키지의 복원은 영구 소유권과 가구만 복원합니다. 사용한 재화·부스터는 중복 지급하지 않으며 기존 클라우드 저장을 통해 복원해야 합니다.

기기 초기화/분실이 **지급 저장과 서버 ACK 사이**에 발생한 경우 자동 판단으로 새 재화를 발행하지 않습니다. 구매 기록을 바탕으로 고객 지원이 확인해야 합니다. 현재 서버는 전체 게임 재화 잔액을 관리하는 권위 서버가 아니라 결제 검증·지급 이력 서버입니다.

## 7. 테스트폰에서 결제 확인

### 7.1 라이선스 테스터 등록

1. Play Console의 **설정 → 라이선스 테스트**에서 테스트폰 Google 계정을 등록합니다.
2. 내부 테스트 트랙을 사용하면 해당 Google 계정을 내부 테스트 명단에도 추가합니다.
3. 테스트 참여 URL을 열어 참여를 완료한 뒤 Play Store에서 테스트 버전을 설치합니다.
4. 개발 APK 직접 설치를 이용할 경우에도 동일 패키지와 라이선스 테스터 조건을 충족해야 합니다.
5. 결제창에서 실제 결제 계정과 **테스트 구매/테스트 결제 수단** 표시를 확인합니다. 일반 카드 결제라면 진행하지 말고 설정을 확인합니다.

OAuth 동의 화면 테스트 사용자, AdMob 테스트 기기, Play 내부 테스트 사용자, Play 라이선스 테스터는 서로 다른 설정입니다. 내부 테스트 사용자만 등록하면 실제 과금될 수 있습니다. [Google 결제 테스트 가이드](https://developer.android.com/google/play/billing/test?hl=ko)

### 7.2 첫 테스트

1. 테스트폰에서 Hive 계정을 연결합니다. 재설치·기기 간 복원에는 동일한 Hive 계정이 필요합니다.
2. 상점을 엽니다. 자동 상품 조회/복원이 끝날 때까지 기다립니다.
3. 별가루 50개가 Google Play 가격으로 표시되는지 확인합니다.
4. 현재 별가루를 기록한 뒤 상품 버튼 → 구매 확인을 누릅니다.
5. Google Play 테스트 결제창에서 승인 테스트 수단으로 완료합니다.
6. 별가루가 정확히 50개 증가하는지 확인합니다.
7. 구매 복원을 반복해도 별가루가 추가로 증가하지 않는지 확인합니다.
8. 앱을 재실행하고 별가루와 구매 상태가 유지되는지 확인합니다.
9. 같은 소모품을 다시 구매해 50개가 한 번 더 추가되는지 확인합니다.

## 9. 실제 판매 전 남은 작업

- Google/Hive 콘솔 상품 설정과 테스트 영수증의 전체 흐름을 실기기에서 검증.
- 안정적인 HTTPS 서버 주소와 상시 실행/DB 백업 환경 준비. 임시 개발 서버 종료 시 결제가 준비되지 않습니다.
- 라이브 Hive 스토어/상품 설정 및 서버 `HIVE_ZONE=live`, 실제 판매 허용값 검토.
- 앱 Android Hive 환경도 라이브로 맞춰 재빌드.
- 환불/구매 취소 이후 이미 지급한 재화 회수·VIP 해제 정책과 운영 처리를 마련해야 합니다. 현재 구현은 **검증 시점의 취소 영수증을 거절**하지만, 지급 완료 후 환불 통지를 받아 자동 회수하는 기능은 포함하지 않습니다.
- 환불 통지 연동(RTDN 또는 Hive 제공 알림), 고객지원 복구, 잔액 서버 관리가 필요하면 별도 후속 구현.
- 계정 영구 삭제/개인정보처리방침·스토어 정책 신고는 실제 서비스에 맞춰 확정.
- 구매일부터 28일권을 판매하려면 현재 시즌 상품과 다른 기간 저장 정책이 필요합니다. 현재 시즌 설명을 유지하세요.

- Hive Android SDK 26.4.0 Google IAP 모듈 포함 및 debug/release 플러그인 컴파일 통과.
- 외부 ngrok 상태 조회: 기존 `{"status":"ok"}` 응답 확인. **새 서버 코드 반영·재시작 필요**.
- 실제 Google 테스트 결제 승인·거래 완료: 콘솔 상품/라이선스 테스터 및 서버 반영 후 확인 필요.
- APK 빌드와 Galaxy Note10+(SM-N971N) 덮어 설치·실행 확인. 기존 플레이 데이터 유지, 상점 새 UI와 복원 버튼 확인.
- 최종 APK: `output/JellyMon.apk`, 테스트폰 최종 업데이트 확인 시각 `2026-09-10 18:56:10 KST`. APK의 Google Billing 권한과 Hive IAP/Google BillingClient 클래스 포함 확인.
- 실기기 Hive 상점 초기화 결과: `IAPV4ResponseError(-6100011)`, SDK 상세 원인 `Invalid market pid list`. Google 상품 목록을 받을 수 없는 상태입니다. Hive 상품의 marketPid 목록, Android App ID 연결, Sandbox 상품 설정을 먼저 확인해야 합니다. 설치 오류나 기존 Google 로그인 오류와는 다른 단계입니다.

### 현재 오류 해결 순서

1. 3장의 8개 상품을 Google Play에 등록하고 구매 옵션을 활성화합니다.
2. Hive의 `[3674] JellyADtest` → Google/Android `com.jellymon.game`에 같은 marketPid가 등록되었는지 확인합니다.
3. Hive 스토어 라이선스 키/마켓 계정과 Sandbox 설정을 확인하고 저장합니다.
4. 6장대로 새 서버를 배포하고 `billing:true`를 확인합니다.
5. 테스트폰 상점의 **구매 복원 / 상품 새로고침**을 누릅니다.
6. 가격이 정상 표시되면 라이선스 테스터 결제창으로 테스트합니다.
