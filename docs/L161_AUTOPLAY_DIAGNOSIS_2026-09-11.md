# L161 자동 탐색 실패 재확인 · 2026-09-11

## 판정

**미해결 1건이 맞다.** 현재 코드에서 81수 후 젤리 4개가 남는 실패를 다시 재현했다. 자동 탐색의 실패는 확인했지만, 시작 상태에서 레벨 자체가 풀리지 않는다는 증명도, 정상 클리어 경로도 확보하지 못했다. 출시 검증 완료로 변경하지 않는다.

이번 확인에서는 실험용 탐색 변경을 되돌렸으며 게임 규칙과 레벨 데이터에 수정 사항을 남기지 않았다. 테스트폰의 설치본과 사용자 저장 데이터도 변경하지 않았다.

## 재현

Godot 4.7에서 프로젝트 루트 기준으로 실행한다. `GODOT_BIN`은 설치된 Godot 실행 파일 경로다.

```sh
"$GODOT_BIN" --headless --path . --log-file /tmp/jellymon-l161.log -- --autoplay-level=161 --trace-autoplay
```

기본 탐색의 핵심 출력은 다음과 같다. 로그의 `level=160`은 내부 0부터 시작하는 인덱스이며 사용자 화면의 L161을 뜻한다.

```text
[autoplay] catcher=1 cell=(1, 4) color=R capacity=1 locked=false
[autoplay] catcher=2 cell=(4, 8) color=Y capacity=3 locked=false
[autoplay] jelly=(3, 4) color=Y personality=sleepy
[autoplay] jelly=(3, 5) color=Y personality=
[autoplay] jelly=(4, 7) color=R personality=
[autoplay] jelly=(5, 7) color=Y personality=playful
ERROR: [autoplay] route search exhausted: level=161 moves=81 left=4 (not proof of an unsolvable level)
[smoke] level=160 state=play moves=81 limit=0 left=4 catchers=2
```

종료 코드는 1이다. 인증서 초기화 오류와 별개로 실제 자동 플레이가 `state=clear`에 도달하지 못한 결과다.

## 확인된 막힘과 원인 후보

좌표는 왼쪽 위가 `(0, 0)`이다. 남은 빨간 세로 4칸 블록은 수용량 1, 노란 가로 4칸 블록은 수용량 3이다. 빨간 젤리 `(4, 7)`이 노란 블록의 위쪽 이동을 막고, 노란 젤리들은 빨간 블록의 접근을 제한한다. 탐색기가 앞서 선택한 빨간 블록별 흡수 순서와 수용량 소모가 원인 후보지만, 다른 순서로 완주하는 경로를 얻지 못했으므로 근본 원인으로 확정하지 않는다.

`scripts/Game.gd`의 자동 탐색은 가까운 목표 선택, 수용량 예약, 제한된 후속 탐색으로 이동을 결정한다. `_debug_terrain_reach()`는 지형과 일방통행을 바탕으로 도달 가능성을 계산하며 다른 젤리와 블록을 모두 반영한 완전 탐색이 아니다. `_debug_can_finish_catcher()`도 제한된 탐욕 탐색을 사용한다. 따라서 정적 검사 통과가 순서 체인·성격 젤리를 포함한 실제 런타임 완주를 보장하지 않는다.

## 추가 시도 결과

| 시도 | 결과 |
|---|---|
| 현재 코드의 기본 자동 플레이 | 81수, 4개 잔여, 실패 재현 |
| 블록 탐색 시작 순서를 1~7로 변경 | 모두 81수, 4개 잔여로 실패 |
| 후속 탐색 예산 소진 시 보수적으로 거부 | 70수, 4개 잔여로 실패 |
| 도달 가능성 계산에 다른 색 젤리 반영 | 수용량 예약이 과도하게 제한되어 진행 실패 |
| 마지막 흡수 외의 흡수에도 후속 탐색 적용 | 34수, 13개 잔여로 실패 |
| 빨간 두 블록의 담당 젤리를 제한한 실험 경로 | 17수, 16개 잔여로 실패 |

이 실험들은 해결책이나 수동 클리어 증거가 아니다. 탐색 순서를 단순 변경하는 것으로 해결되지 않았다는 진단 근거다.

## 완료 조건

1. 시작 상태부터 클리어까지 이어지는 합법적인 이동 경로를 확보한다. 현재는 미확보다.
2. 해당 경로를 실제 이동·도착·흡수 처리로 재생해 순서 체인, 성격 젤리, 일방통행, 수용량과 시간 제한을 검증한다.
3. 경로가 확보되면 탐색기와 실제 규칙의 차이를 수정하고 회귀 검증에 포함한다. 레벨 수정이 필요하면 데이터 변경 후 다시 검증한다.
4. L161 개별 검사와 `--validate-endgame` 전체 검사가 모두 통과한 뒤 미해결 목록에서 제거한다.
