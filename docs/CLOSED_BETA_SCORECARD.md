# 젤리몬 클로즈드 베타 9.0 품질 게이트

코드와 콘텐츠의 존재만으로 9점을 선언하지 않는다. 30~100명의 신규 플레이어가 아래 게이트를 통과해야 재미·리텐션·과금 설계를 9.0 후보로 판정한다.

## 테스트 구성

- 최소 30명, 권장 100명. 개발팀·지인 계정은 별도 코호트로 분리한다.
- 7일 동안 동일 빌드를 사용하고, 힌트나 공략을 제공하지 않는다.
- `assets/data/analytics_remote.json`의 HTTPS 수집 주소를 설정해 익명 이벤트를 전송한다.
- 원본 기기 ID는 전송하지 않으며 게임 전용 단방향 `player_key`만 사용한다.
- 서버 미연결·오프라인 이벤트는 최대 500개까지 보관한 뒤 자동 재시도한다.

| 영역 | 내부 합격선 |
|---|---:|
| 첫 실행 후 LEVEL 1 시작 | 90% 이상 |
| LEVEL 1 클리어 | 85% 이상 |
| LEVEL 10 도달 | 55% 이상 |
| 첫날 세션 2회 이상 | 40% 이상 |
| D1 재방문 | 35% 이상 |
| D7 재방문 | 12% 이상 |
| 초반 20레벨 평균 실패 후 이탈 | 12% 이하 |
| 시그니처 장면 재미 설문 | 5점 만점 4.3 이상 |
| 젤리몬 애착 설문 | 5점 만점 4.3 이상 |
| 선택형 보상 광고 수락률 | 25% 이상 |
| 시즌·꾸미기 구매 의향 | 10% 이상 |

## 필수 분석

1. `--analytics-report`로 로컬 퍼널을 먼저 확인한다.
2. 레벨별 `start → clear/fail → next start` 전환을 비교한다.
3. LEVEL 5·10·15…50의 `signature_moment` 시작/완료 누락을 확인한다.
4. 연속 3회 실패 레벨은 시간보다 이동 가능성과 목표 전달을 먼저 재검토한다.
5. 상품 노출 후 구매 대신 이탈이 늘면 노출 타이밍을 제거한다.

합격선에 미달한 항목은 시스템을 더 추가하지 않고 해당 퍼널과 레벨을 우선 수정한다.
